## 1. 提示词体系设计

### 1.1 为什么需要分层
当前 `agent_runner.py` 写死一段中文 `system_prompt`，所有约束混在一起，导致不可配置、不可组合、职责不清。
提示词分层 = 把「角色 / 知识 / 行为 / 风格」四维解耦，各自独立可调、可组合。

### 1.2 四层提示词架构

| 层 | 名称 | 作用 | 落地位置 |
|---|---|---|---|
| L1 | **系统提示词** `system_prompt` | Agent 身份、目标、全局行为规则 | `src/prompts.py` |
| L2 | **知识库/检索提示词** `rag_prompt` | 如何使用检索结果：只依据资料、标注来源、禁止编造 | 拼接进 system_prompt |
| L3 | **回答模式提示词** `reply_prompt` | 简洁 / 标准 / **报告** 三档模板，动态切换 | `config.REPLY_MODE` + 模板 |
| L4 | **工具调用提示词** `tool_prompt` | 何时调工具、参数说明 | 由 AgentScope 工具 schema 驱动 |

> 组合原则：`最终 prompt = L1 角色规则 + L2 检索规范 + L3[当前模式] 风格模板`。L4 不进 system prompt（由 AgentScope 工具 schema 驱动）。

### 1.3 L1 · 系统提示词
见 `src/prompts.py` 的 `L1_SYSTEM`（角色 + 全局规则，含"先检索只依据资料""调工具不心算""不得编造""演示语料提醒官方为准"）。

### 1.4 L2 · 知识库/检索提示词（防幻觉）
见 `src/prompts.py` 的 `L2_RAG_RULES`（以检索片段为唯一来源、标注来源、矛盾时说明差异、弱相关提示）。

### 1.5 L3 · 回答模式切换（简洁 / 标准 / 报告）

| 模式 | 风格 | 适用 |
|---|---|---|
| `brief` 简洁 | 3~5 句结论优先 | 快速问答 |
| `standard` 标准 | 结论 + 关键依据 + 表格/分点 | **默认** |
| `report` 报告 | 摘要/分节/数据表/假设与风险/建议/免责 | 交付报告 |

**切换入口：**
1. 配置默认：`.env` 的 `REPLY_MODE=standard|brief|report`
2. 命令行：`python scripts/main.py --mode report`
3. 自然语言（可选）：问题含"写份报告/详细" → report；含"简单/一句" → brief

### 1.6 实现
- `src/prompts.py`：集中 4 层模板 + `build_prompt(city, mode)` 组装
- `config.py`：加 `REPLY_MODE`
- `agent_runner.py`：用 `build_prompt(config.CITY, config.REPLY_MODE)` 注入
- `scripts/main.py`：支持 `--mode` 覆盖 + 自然语言识别

## 2. 个税计算改进方案（Phase 3，待做）

### 2.1 现状与边界
- 已修复：月度三档速算，2 万 → 到手 ≈ 15,560
- 边界：**演示级真实**；明确不做完整累计预扣法

### 2.2 改进点 A：缴费基数上下限（clamp）
- `CITY_PARAMS` 每城加 `base_floor / base_cap`；`base = min(max(salary, floor), cap)`
- 学习点：工具参数化与领域建模边界

### 2.3 改进点 B：专项附加扣除参数化
- `compute_salary(city, salary, deductions=0.0)`，应纳税所得额减去 deductions
- 学习点：向后兼容的函数设计（默认参数）

### 2.4 改进点 C：输出估算区间
- 输出区间 + 关键假设一行，而非伪装精确
- 学习点：不确定性表达、负责任的 AI 输出

### 2.5 与提示词联动
- 工具负责"算"，Agent 负责"解释"：L1 规则 4 + report 模式的"影响因素"章节
