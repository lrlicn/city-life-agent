## 一、项目定位

**城事小灵通智能体** —— 结合「RAG 政策检索 + ReAct 工具调用」的城市生活成本计算 Agent：

- 先检索目标城市的政策语料（社保/公积金/租房/通勤等），再调用计算工具给出**可溯源、可核验**的答案
- 城市可配置：换城市 = 改 `.env` 的 `CITY` + 在 `data/docs/{CITY}/` 放语料 + 扩 `CITY_PARAMS`，不改架构
- 本质是一条 **ReAct 推理循环**，四个体系在循环的不同位置介入：

| 体系 | 管什么 | 介入位置 |
|---|---|---|
| 提示词 | 怎么想 | 入口（system prompt 注入） |
| RAG | 拿什么 | 信息源（search_knowledge 工具） |
| ReAct | 循环骨架 | THINKING → TOOL_CALL → TOOL_RESULT → TEXT |
| 权限 | 能不能调 | 工具调用处闸门（BYPASS / 审批） |

## 二、后端能力现状（`src/` + `api/`）

### 2.1 技术栈

Python 3.14 + AgentScope 2.0 + Qdrant（本地向量库）+ 阿里云百炼（OpenAI 兼容端点）+ Starlette SSE + SQLite（WAL）。

### 2.2 模块职责

| 文件 | 职责 |
|---|---|
| `src/config.py` | 统一读取 `.env`（API_KEY / BASE_URL / MODEL / CITY / REPLY_MODE 等） |
| `src/prompts.py` | 四层提示词体系 + `build_prompt()` 组装 + 自然语言模式识别 |
| `src/rag_build.py` | 建库：解析 → 切块(overlap) → embedding → Qdrant 持久化 |
| `src/tools.py` | 7 个自定义工具（见下表），全部带「演示参数、以官方为准」免责口径 |
| `src/agent_runner.py` | Agent 组装：RAGMiddleware(agentic) + Toolkit + 权限链路 |
| `src/interaction.py` | 进程内交互总线：SSE 不断流「暂停 → 用户点选 → 续跑」 |
| `src/db.py` | SQLite：conversations / messages / bookmarks 持久化 |
| `api/server.py` | SSE 后端：`/chat-ai`（AI SDK 协议）+ 会话/收藏/交互/下载 REST |
| `scripts/main.py` | CLI 入口：建库 → 检索演示 → Agent 问答（`--mode` / `--ask`） |

### 2.3 工具清单（ReAct 可调用）

| 工具 | 功能 | 生成式 UI part | 前端图表 |
|---|---|---|---|
| `compute_salary` | 到手工资：基数上下限 clamp、专项附加扣除、估算区间、口径说明 | `data-salary` | SalaryChart |
| `compute_rent` | 租房成本：押金/中介费/首月一次性/月均/年总 | `data-rent` | RentChart |
| `compute_commute` | 通勤开销：地铁/电动车/自驾/打车四种方式月成本对比 | `data-commute` | CommuteChart |
| `compute_mortgage` | 房贷：商贷/公积金/组合贷 × 等额本息/等额本金，公积金按城市上限自动封顶拆分 | `data-mortgage` | MortgageChart |
| `compute_cost_index` | 多城市生活成本指数（基准=100，租房/餐饮/交通/日用四类） | `data-cost-index` | CostIndexChart |
| `ask_user` | 生成中途暂停，给用户 2~4 个互斥选项点选澄清 | `data-interaction`(choice) | 选项 chip |
| `export_report` | 报告正文落盘 `data/exports/*.md`，返回下载链接 | `data-export` | 下载卡片 |
| `search_knowledge` | RAGMiddleware agentic 模式内置的检索工具 | — | — |

**工具输出契约**：所有计算工具输出**固定行式文本**（如 `社保(个人) ≈ 1234 元`），后端 `api/server.py` 用正则提取结构化数据 → 下发 `data-*` part → 前端画图。**新增工具必须同时改两处**：`tools.py` 定义 + `server.py` 加 `_parse_xxx_output` 与下发分支。

### 2.4 关键机制

- **提示词体系**（`prompts.py`）：
  - L1 系统规则（角色 + 全局铁律：先检索只依据资料 / 调工具不心算 / 房贷区分贷款类型 / 缺参用 ask_user / 导出走 export_report / 不得编造 / 排版规范）
  - L2 检索规范（防幻觉：唯一来源 / 标注出处 / 矛盾说明差异 / 弱相关提示）
  - L3 回答模式三档：`brief`（3~5 句结论优先）/ `standard`（默认，结论+依据+表格）/ `report`（六节正式报告）
  - 切换入口：`.env` REPLY_MODE、请求体 mode、自然语言关键词（`detect_mode_from_question`）
- **权限链路**（`agent_runner.py`）：默认 `PermissionMode.BYPASS` 全放行；`require_approval=True` 时切 `DEFAULT`，对 6 个「行动类」工具加 ask_rules（弹审批卡片），`search_knowledge`/`ask_user` 加 allow_rules 免打扰
- **交互总线**（`interaction.py`）：`asyncio.Future` 注册/唤醒。澄清类走 args_hash 跨注册命中；审批类纯 interaction_id。超时 600s 降级（澄清→引导模型合理假设；审批→默认拒绝）
- **多轮记忆**：`/chat-ai` 按 conversationId 从 SQLite 取最近 20 条文本消息转 Msg list 回喂
- **会话标题**：新会话首轮后台并发生成 AI 总结标题，前端流式期间轮询对账（临时 id → 真实 id）
- **分支重生成**：`POST /api/conversations/{id}/truncate` 从第 N 轮起截断旧链，前端「重新生成/编辑重发」复用

### 2.5 API 路由一览

| 路由 | 方法 | 功能 |
|---|---|---|
| `/chat-ai` | POST | AI SDK 5 Data Stream（SSE），前端 useChat 主入口 |
| `/chat` | POST | 简易单轮 SSE（验证页用） |
| `/api/conversations` | GET / POST | 会话列表 / 新建 |
| `/api/conversations/{id}` | PATCH / DELETE | 重命名 / 删除 |
| `/api/conversations/{id}/messages` | GET | 历史消息 |
| `/api/conversations/{id}/truncate` | POST | 分支截断 |
| `/api/bookmarks` (+/{bm_id}) | GET/POST/PATCH/DELETE | 收藏笔记本 CRUD |
| `/api/interact` | POST | 前端回传点选/审批，唤醒阻塞的 SSE |
| `/api/exports/{filename}` | GET | 下载导出的报告（限 data/exports，防目录穿越） |

## 三、前端界面风格现状（`web/`）

### 3.1 技术栈

Vue 3（`<script setup>`）+ Vite + Vercel AI SDK（`@ai-sdk/vue` useChat 流式）+ ECharts 6 + marked（Markdown 渲染）。无 UI 组件库，全自写样式。vite 代理 `/chat-ai` 等到后端 8000。

### 3.2 主题系统

- 全部颜色由 `web/src/assets/theme.css` 的 **CSS 变量**驱动，两套：`:root`（深色默认）+ `[data-theme="light"]`（浅色覆盖）
- 三档切换（浅色/深色/跟随系统）由 `Sidebar.vue` 设置浮层 + `ThemeToggle.vue` 控制，localStorage 持久化，「跟随系统」用 JS 解析后落到深/浅两套
- **品牌色薄荷绿**：深色用亮薄荷 `#5AF9CB`（mint-on-dark 高对比），浅色压暗为祖母绿 `#0E9E79` 保白底可读
- 深色带氛围光晕渐变背景；浅色纯白极简（光晕 transparent、边框压成薄荷发丝线）
- 聚焦细线用独立变量 `--accent-line`（避免背景填充色糊字）
- 全局 tooltip 单例：元素加 `data-tip="…"` 即可，`src/tooltip.js` 负责显示节奏与智能定位

### 3.3 页面布局（Codex/ChatGPT 风格）

```
┌─────────┬──────────────────────────────┐
│ Sidebar │ 顶栏（会话标题 + 免责提示）      │
│ 品牌头    ├──────────────────────────────┤
│ 新建会话  │ 消息区                        │
│ 会话列表  │  · 用户气泡（可编辑重发/复制）   │
│ （溢出滚动 │  · AI 行：头像 + 思考/工具折叠   │
│  标题marquee）│    面板 + Markdown 正文      │
│ 收藏笔记本 │    + 图表(沉底) + 交互/导出卡片  │
│ 设置浮层   │  · msg-meta：复制/重生/收藏/    │
│（主题+审批）│    导出MD/打印PDF + 时间/耗时    │
├─────────┤ 左侧轮次导航条 turn-rail(minimap)│
│ Bookmarks │ ─────────────────────────────┤
│ 抽屉      │ 输入条 composer（大胶囊）        │
└─────────┴──────────────────────────────┘
```

### 3.4 交互亮点

- **首屏**：居中大输入框 + 问候语（"城市生活的账，帮你算清楚"）+ 2 列 6 张预设问题卡片（覆盖全部工具能力）；聚焦输入框时建议区淡出
- **流式版式同构**：生成中与历史视图一致——思考/工具归入顶部折叠面板，正文只长文字，图表统一沉底（避免版式跳变）
- **工具卡片**：思考过程合并面板 + 每个工具可展开查看输入参数/返回结果
- **轮次 minimap**：每轮一条短横线，hover 延长弹预览，点击滚动定位，可从任意轮重新生成（分支截断语义）
- **消息操作**：复制、重新生成（truncate 后重发非平行分支）、编辑重发、收藏、导出 Markdown（前端 Blob）、打印/存 PDF（新窗口注入渲染 HTML）
- **中途交互**：ask_user 选项 chip（点选后 SSE 原地续跑）、审批卡片（批准/拒绝/超时回显），历史只读回显当时决策
- **审批快捷开关**：输入条上「需审批/免审批」chip 与 Sidebar 设置面板共享 `useSettings.js` 单例（localStorage）
- **图表去重**：同类图按关键入参（城市+薪资等）去重，只保留最后一张
- 图标统一线性 stroke 风格，`currentColor` 继承主题

| `SalaryChart/RentChart/CommuteChart/MortgageChart/CostIndexChart.vue` | 五类生成式 UI 图表（ECharts） |

## 五、已知问题与可改进方向（复盘结论）

### 5.1 文档滞后（建议优先同步）

- README「学习进度/后续计划」与代码不符：**通勤(Phase3)、房贷(Phase4)、生活成本(Phase5)、ask_user 澄清、export_report 导出、HITL 审批、消息操作、分支重生成、收藏笔记本均已完成**，但清单仍标记未完成（如 "Human-in-the-loop 审批弹窗"、"消息操作" 实际已实现）

- 设计文档 §0「现状盘点」仅覆盖到个税 Phase3，未反映后续扩展
